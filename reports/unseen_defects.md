# Unseen defect types on VisA pcb1 (Phase 4b)

Generated by `scripts/render_unseen.py` from `reports/unseen/pcb1_*.json` (one file per run of `scripts/run_unseen.py`); nothing is typed by hand (the commentary lives in the notes file and README.md). **Small sample:** see the image counts per defect type below; every interval is wide.

## Protocol

- One run per held-out defect type T, plus a control run that holds nothing out. The detector is Faster R-CNN ResNet50-FPN v2 (COCO-pretrained), class-aware, with a class for every defect type except T. It trains on `threshold_calibration` anomalies with exactly one defect type (never T; the mask cannot be split by type for an image with several) and a fixed random sample of `train` normal images as negatives. Boxes come from the VisA masks (`data/visa_to_coco.py`). The recipe is fixed in `configs/unseen/pcb1.yaml` before any run: no validation set, no checkpoint selection, the last epoch is used.
- The anomaly models are the Phase 3a/3b checkpoints (trained on `train` normals only, no anomaly seen), the same for every T.
- Every model gets one operating point per false-alarm budget: the lowest threshold whose false-alarm rate on the `threshold_calibration` **normal** images is at most the budget. Scores of anomalous images never enter a threshold. An image is flagged when `score >= threshold`; a detector's image score is its highest box score. These are not the cost-based thresholds of Phase 4a (those are frozen and untouched).
- Recall is image-level on `threshold_evaluation`: *unseen* = anomalous images that contain T, *seen* = those that do not. An image counts as caught if it is flagged, wherever the evidence is (for the detector: any box, not necessarily on the defect), which is generous to both kinds of model. Intervals are 95% Wilson intervals.
- `threshold_evaluation` was already used once, for the frozen Phase 4a thresholds, and is read again here for a different question with thresholds set on calibration normals only; no Phase 4a threshold or result changes.
